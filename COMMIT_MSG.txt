BuildBuddy v1.3 fix freeze when applying large deliveries

WHY
Applying a delivery with many files could freeze the window with no way to close it.
The console showed the unzip finishing and then the app hung. The cause was output
flooding. The previous code hopped to the main thread once per output chunk and forced
a full console re render each time, so a delivery with dozens of files spawned hundreds
of updates and saturated the main thread.

FIX
Command output is now buffered on a background queue and flushed at most about eight
times per second instead of once per chunk. The console is capped to a recent window so
the text view never rebuilds an unbounded string. The preview unzip now runs in quiet
mode so a large delivery does not print one line per file. Final output is flushed once
the command exits, and the flush timer is always cancelled.

NOTE
Because this drop replaces the app source, relaunch BuildBuddy after applying so the
launcher rebuilds from the new source.

FILES CHANGED
BuildBuddy.swift and Launch BuildBuddy.command.
